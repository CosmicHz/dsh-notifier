# UX缺口审查：当前规格，不是成品界面

审查日期2026-10-05。对象：执行包2.0的06 UI、02数据、03 RPC、TASKS。尚无运行中的v1界面，因此下列是规格级缺陷，不声称观察到真实用户行为。
品质目标：以Awwwards、Webby Awards、FWA优秀数字产品的视觉完成度、清晰交互和细节作为方向；这不是对其官方评选规则的复述，也不构成获奖保证。工具界面的工作效率、无障碍、宿主一致性优先于展示性特效。

|编号|严重度|缺口|用户成本|定稿修正|
|---|---|---|---|---|
|UX01|阻断|首屏直接暴露账号、目标、路由|用户先学习数据模型才知道做什么|任务入口：接收通知/在手机上回复；隐藏内部模型术语|
|UX02|高|把所有平台字段照schema平铺|用户不知道去哪获取凭据、填错怎么改|渠道编辑说明注册表；每字段标签、用途、来源、示例、错误和敏感说明|
|UX03|高|添加账号与目的地是两套独立CRUD|填完账号仍无法接收，产生假完成|一个连接向导一次提交账号+目的地，原子后端方法|
|UX04|高|保存与测试被写成两个孤立操作|用户不确定已保存还是失败需要重填|一个主按钮“保存并测试”，阶段明确，测试失败保留已保存配置|
|UX05|高|账户存在被当作设置成功|没有可投递目标也显示ready|设置完成以目标存在和配置有效为准，发送测试另显示证据|
|UX06|高|只有accounts.list没有运行时health合同|界面自己推断“在线”|明确运行状态投影，持久配置和transport状态分开|
|UX07|高|accepted/confirmed等术语直接展示|把平台接受误读为消息已到达|中文人话主标签+“查看技术详情”，证据不变|
|UX08|高|私聊/成员/会话/权限一次性展开|首次配对要求理解完整权限系统|配对三步；默认本人owner；成员和会话权限位于高级区域|
|UX09|高|pending只列类型和按钮|看不到谁请求、影响什么、现在应做什么|任务来源、请求内容、风险相关上下文、期限与动作固定层级|
|UX10|高|错误依赖toast/原始code|消失后无恢复入口，不能判断是否保存|字段内错误+持久操作结果+唯一下一步，toast仅附加|
|UX11|高|删除确认只问“确定吗”|误删授权/目标，后果不透明|显示连接名称、受影响目标/成员数量；禁用可逆，删除明确不可逆|
|UX12|高|断线/冲突刷新覆盖用户输入|重复填写和重复发消息|内存草稿保留；刷新仅更新服务器副本；显式对比重填|
|UX13|中|五页平均卡片网格|信息没有优先级，像默认后台模板|每页专属布局，概览任务导向，通知有序列表，待办单焦点|
|UX14|中|泛化40px控件、无类型与密度细则|窄屏拥挤，中文阅读和英文换行差|44px触达，类型层级、行长、视口密度与长文本规则固定|
|UX15|中|无统一图标和视觉节奏|不同页出现不同风格和“拼装感”|统一几何线性图标、克制色彩、行列节奏与边框层级|
|UX16|中|未定义动效用途|实施者用装饰动画或完全没有反馈|只对状态/导航/展开使用有界动效，reduce-motion完整支持|
|UX17|高|导入只在CLI，首次用户可能误以为必须迁移|旧数据阻塞新用户理解|明确“直接开始新配置”，导入仅设置高级里的可选能力|
|UX18|高|40张截图检查无法覆盖错误/等待/权限|漂亮空页面掩盖真实交互缺陷|增加复杂fixture、错误/断线/冲突/大量数据和键盘证据|
|UX19|高|没有成品视觉自审流程|模型写完CSS就称高品质|三轮render→inspect→fix，逐条问题、截图、复核证据|
|UX20|中|扫码范围与历史要求不明确|实施者随意删登录入口|按渠道清单明确可用登录方式；凭据输入有完整辅助，不显示虚假二维码按钮|

修订关系：11修正UX01–12/17，12修正UX13–16，13修正UX18–19；14固定新增RPC并让原子设置和health可实现。UX20按04固定方式，不扩展未验证协议。
