# 固定信息架构与交互：从用户任务开始

本文件定义唯一用户流程；06不重复定义。产品对外名称“通知与控制 / Notify & Control”。顶层五项固定：概览 Overview、通知 Notifications、手机控制 Mobile control、待处理 Inbox、设置 Settings。内部PrivateChatPage文件名不变。数据实体Account在UI叫“连接”，Destination叫“接收位置”；原则是少暴露概念，不改变后端数据模型。

## 术语与理解成本

一级界面禁止出现schema、epoch、revision、CAS、RPC、provider、principal、配置投影。连接高级详情允许“技术详情”展示脱敏错误码/版本。路由在UI叫“通知发送规则”，用户可在高级中按代理/会话/工作区设置。
每页一个页面标题、一句用途说明、一个页级主动作；危险动作不能用与主动作同样的强调色。表单不超过6个默认可见字段，其他折叠为“更多选项”。渠道搜索支持中英文名称和别名，但不向core传旧ID。

## F-A 首次使用

概览空态：标题“任务有进展，及时收到消息”；说明“选择你常用的应用，先连接一个接收位置。之后可以开启手机回复。”主按钮“设置通知”，次按钮“设置手机控制”。不显示0账号/0待办的统计墙、不弹迁移要求。
向导固定3步：①选择应用 ②连接与接收位置 ③测试结果。顶部Step 1 of 3，当前步骤名称和返回，退出有未保存提示。
1. 默认显示全部渠道的紧凑可搜索列表，按中文名称排序；本地提醒单独一组置底。最近使用为空时不伪造推荐热度。选中只有一个，展示“可接收通知/也可手机回复”能力标签。
2. 标题“连接Telegram”等；字段按spec/EDITOR-FIELDS.json生成说明。接收字段在同一页“发送到哪里”分区。凭据用途说明：“凭据仅保存于当前DSH设备，不会显示在活动记录中。”必须符合后端实际实现。
3. 主按钮“保存并测试”。先调用connections.create，成功即记已保存，再调用notifications.test；显示“正在保存…”→“正在发送测试…”。发送失败显示“连接已保存，测试未成功”及“重试测试/编辑连接”；不删刚保存的记录，不要求重填。
4. accepted显示“平台已接受测试消息”，说明“请打开对应应用确认是否收到”；confirmed显示“平台已确认送达”；uncertain显示“暂时无法确认发送结果”，先引导查收，重试须确认可能重复。
5. 完成后显示“返回概览”和在支持入站时的“开启手机控制”。首个目标明确默认被选为通知目标，提交前文案“将此位置设为默认接收位置”复选框默认选中；不是自动偷写全局路由。

## F-B 通知日常管理

有配置后显示连接列表，每行：渠道图标/名称、连接名、接收位置摘要、通知状态、最近测试/错误时间，右侧“测试”和更多。不是每连接一张巨大统计卡。
新增按钮“添加连接”；详情在侧边panel，<=719px为全屏panel，同一表单组件。列表保留滚动位置；关闭回到原连接。接收位置可增删改，公开目标字段在技术详情之外清楚标注，不用ID替代名称。
“暂停通知”是可逆开关，立即给出状态与恢复入口；“删除连接”在更多菜单底部，确认Dialog显示名称/目标数量/已配对人数，“删除后需重新连接和配对”，取消默认焦点。删除失败原列表项保留。

## F-C 手机控制

入口只显示6支持渠道。已有该渠道连接可复用；没有则提供完整连接表单；微信/飞书扫码先创建disabled草稿再login，成功后启用，取消保留可删除草稿。飞书/钉钉通知webhook与控制应用凭据不同，明确两个分区，不能暗示填webhook就能对话。连接成功不等于配对成功。
配对3阶段：连接应用→生成配对码→在私聊发送 /pair CODE。8位明文只在当前Dialog显示，复制按钮复制完整命令；倒计时基于expiresAt，过期主动作变“重新生成”。关闭撤销未核销码；失败保留原因，不能后台无限重发。
成功由principals.list反映，不靠本地计时猜测；说明“已连接你的身份，可接收待办并处理允许的请求”。“允许通过手机继续对话”独立开关默认关。owner/member与session scope放“其他成员与权限”折叠区域；默认配本人，不让用户先理解组织管理。
对话未授权/未选择会话时显示相应唯一下一步，不显示“控制已就绪”。连接断开状态独立于身份配对状态。

## F-D 待处理

默认未处理，按expiresAt最早优先，再createdAt/id。每项显示请求类型、任务名/会话名、请求摘要、到期时间。桌面列表+详情两栏，选中首项但不自动操作；窄屏列表→详情，返回保留位置。
详情顺序：来源与时间→完整请求→必要上下文→选择/输入→操作结果。请求正文必须可展开完整阅读，无固定高度裁掉关键内容。长命令/路径用可滚动等宽区，不横向撑宽主页面。
批准为primary，拒绝为secondary；只有实际有危险上下文时显示对应内容，不给所有审批贴红色。没有足够上下文仍允许拒绝，批准按后端合同判断。提交期间禁重复；过期/已处理立刻去掉可执行动作，结果就地可读。
“没有待处理事项”显示安静空态，不显示完成率或庆祝动画。100条分页50，搜索/类型筛选不丢实际总数。

## F-E 设置与恢复

默认只显示默认接收位置、暂停通知、语言/主题跟随宿主说明。高级折叠：通知规则、数据保留、诊断、导入与备份。导入说明“可选；无法导入的内容可重新设置，不影响开始使用”。CLI命令整段可复制，给出操作结果示例；不制作无后端的导入按钮。
诊断下载仅metadata JSON，点击前说明不含凭据及聊天正文。技术详情显示版本/目标宿主/错误码，首次用户不被迫阅读。

## 固定错误文案与位置

VALIDATION：字段下“请填写…”并在提交后聚焦第一个错误；输入时不每键红字。
CONFLICT：“这项设置已在其他位置修改。你的输入已保留。”按钮“查看最新设置”，禁止自动覆盖。
NETWORK/TIMEOUT：“暂时无法连接{应用}。连接设置已保存。”按钮“重试”，次级“编辑连接”。
STORAGE_UNAVAILABLE：“暂时无法保存设置。”说明“已保存的数据没有被新修改覆盖。”仅在确实未提交时这样写；durability-uncertain必须改为“写入结果需要核对”，禁声称未变。
FORBIDDEN：“当前身份没有此操作权限。”显示“查看权限”仅local-owner，IM不给越权入口。
UNCERTAIN：“操作结果暂时无法确认。请先查看对应应用或任务，避免重复操作。”无自动retry。
断线全局细条：“连接已断开，显示的是{时间}的数据。”重新连上后移除；未保存输入仍在内存。

表单草稿仅组件内存，不将token写localStorage/sessionStorage；退出含secret草稿需确认，离开后清空。刷新不能承诺保存未提交秘密。Toast不是错误唯一载体。
