# 高标准自审与迭代：三轮必须实际渲染

目标是接近优秀获奖数字产品的完成度，不将自评分称为获奖预测。当前包只是设计要求，不能生成虚假的界面审查通过证据。

## 三轮流程

R1视觉原型：T30真实壳+概览/通知设计样张就绪后，截图并检查布局、类型、颜色、组件。至少覆盖390/1280、中英、深浅。允许此轮明确标注prototype fixture，不是生产成功证据。
R2完整体验：T31–33实际页面和真实本地后端就绪，跑首次设置、配对、审批、保存失败、断线、冲突；记录每一步是否有明确下一步及可逆退出。
R3修正后复核：修复R1/R2问题，重新拍全部基准图、运行交互测试；比对修复前后，检查局部修复是否破坏其他页面/主题/尺寸。
任一轮出现阻断/高严重度，必须修复再复核；三轮不是上限，也不能以“做够三轮”代替通过。禁止删除差的截图/fixture让审查通过。

## 审查角度（同一执行者逐轮切换，不假装多名用户）

新用户：不知道账号/目标/路由差异，仅想收到第一条通知；指出出现的每个生词与无法回答的下一步。
常用用户：一分钟内找出故障连接、待审批事项和暂停通知入口。
误操作用户：填错凭据、关闭配对、重复点击、删除前取消，检查是否失去已输入内容或产生重复操作。
视觉编辑：按16px/32px节奏查对齐、边距、行高、标题、色彩、符号一致性。
无障碍：只用键盘、200%文字放大、减少动画、读屏标签/错误关联，检查完整流程。
这些是专家式/代理自审，不是人类可用性研究；不得写“用户测试证明”。

## 验收证据矩阵

基础40张：5页×2语言×2主题×2视口390/1280。必须实际打开同一commit客户端截图。
额外至少12组：首次引导、字段错误、保存成功但测试失败、uncertain、配对过期、权限不足、并发已处理、断线stale、编辑冲突、100待办、超长中英名称、空/损坏配置诊断。
360/768回流测试；200%缩放键盘路径；prefers-reduced-motion；输入法组合事件不能触发错误提交；多次Tab切换无重复订阅。
图像参考仅在evidence/visual保存，不进npm包；每张记录route/state/viewport/locale/theme/commit。

## 门槛

零阻断：误批准、误删、秘密泄漏、假成功、核心动作不可达、丢已保存数据。
零高严重度：用户不知道下一步、错误无恢复、配对状态误导、主要控件溢出、键盘陷阱、低对比文字、断线数据冒充实时。
所有已记录的可修视觉缺陷关闭；环境固有限制单列，不能用“差不多”关闭。没有凭据的provider状态用fixture标识，不要求真实账号。
启发式评分每项0–5，5为完整符合规格且无未关闭问题：任务清晰、信息层级、表单/错误、视觉一致性、交互细节、无障碍、响应式、性能。每项>=4，平均>=4.5；分数必须附截图/步骤依据。分数是自检辅助，不能覆盖上述硬门槛。
性能延续07；新动效/插图不能降低操作响应，禁止用动画等待掩盖网络状态。

## 每轮输出格式

evidence/ux/R1.json（R2/R3同）={round,commit,reviewType:'self-review',screenshots:[],journeys:[],findings:[{id,severity,location,observation,userImpact,fix,test,evidenceBefore,evidenceAfter,status}],scores:{},unresolved:[]}。
截图检查必须调用可用图像查看/浏览器截图工具实际观察，不能只通过DOM断言声称审美合格；工具不可用则将视觉审查标未完成，不伪造评分。
